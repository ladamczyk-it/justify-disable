# Docs site

## Why the pages are shaped this way

> Source: documented from plan

The end-user docs are the one page that lives in the author's CV site, moved here verbatim and split into an `index.mdx` plus six flat `.md` pages (the rule, command line, configuration, todo conditions, JavaScript API, usage statistics). The split is by sidebar page only: prose, tables and code blocks were not reworded, so the CV page stays a faithful reference for the content.

The pipeline that regenerates the docs on each release tag can only write `website/docs/**/*.md` and the stamp line of `index.mdx`. Three rules follow from that:

- Split pages must be `.md`, never `.mdx`. `publish-docs.sh` rejects any non-`.md` change under the docs, so an `.mdx` split page could never be updated again.
- Split-page front matter holds only `title`, `sidebar_position` and `description`, with no backslash and no `mdx` in it. `description` values are quoted because a YAML plain scalar cannot start with `@` or a backtick. The quote style is single, because Prettier (run by `qoq:fix`) rewrites it; the pipeline does not check it.
- `index.mdx` carries exactly one "verified against" stamp, and no other page does. `update-docs.sh`, `check-docs.sh` and `publish-docs.sh` share the one regex that reads it. A stamp that is missing or doubled fails the docs run at its first step, since `update-docs.sh` and `check-docs.sh` both exit 1 unless exactly one is found. A placeholder stamp such as `v0.0.0` is lower than any tag, so it makes the next tag regenerate the docs from scratch; it must never be committed.

Links between pages use relative `.md` paths, not `#anchors`. `onBrokenLinks: 'throw'` fails the build on a dead page link, but a broken anchor only warns, so anchors would rot unnoticed.

## Who owns what

> Source: documented from plan

`website/docs/**` is regenerated by CI and `website/src/pages/**` is maintainer-owned. The pipeline scripts, `.woodpecker/docs.yml`, `website/.npmrc` and `qoq.website.js` are copied unchanged from the project Template, so a local edit would be overwritten by the next Template sync. Because every release tag pushes a docs sync commit to main, pull before publishing.

## Homepage, logo and footer

> Source: documented from plan

The homepage is the structurelint pilot's page with justify-disable's copy, kept to the same JSX tree and class names so the two sites stay comparable. It is built to fit one 1440x900 screen without scrolling (title, opener, Get Started beside the install command, the animation, three feature boxes), which is why `index.module.css` is a verbatim copy of the pilot's: the animation's height is then the only variable. That fit is checked by eye, not by a test.

`docusaurus.config.ts` replaces the Theme's shared logo and favicon with the tool's own mark (a comment block with a check). The footer links the author's name to adamczyk.ovh by string-replacing it inside the Theme's copyright text. That is a deliberate shortcut, to move into the Theme so every site gets it; until then the replace silently does nothing if the Theme rewords the copyright.

`@theme/CodeBlock` has no type declaration under `@docusaurus/module-type-aliases` alone, so `@docusaurus/theme-classic` is a devDependency and is listed in the `types` of `website/tsconfig.json`, as in the pilot. Template sync overwrites that tsconfig and would drop the type; this is recorded as a Template finding and not worked around here.

## The animation

> Source: documented from plan

`DisableAnimation` replays one 12 s loop of justify-disable's own job on a mock `src/app.ts`: a scan checks the directive that has a `@todo` directly above it, flags the one that doesn't (a blank line separates it from its comment), prints the failing output, slides in a `@todo` row, and reruns to a pass. The terminal strings are the real output of `src/format.ts` and `src/scan.ts`, pinned as literals, so a change to those messages should be mirrored here. "24 files scanned" is a settled figure: the mock stands for a whole-repo run.

The base CSS is the final, passing frame, so reduced motion only switches the animations off and shows that frame. The panel is no taller than the pilot's (9 code rows, 3 terminal lines) to protect the one-screen fit. The wrapper is 760px wide rather than the pilot's 720px so the longest `@todo` row fits; this was not checked in a browser.

Code lines come from a const array rendered as `{line}`, never as JSX text, because `// ...` and `/**` children trip `@eslint-react/jsx-no-comment-textnodes`. The failing line is likewise a const, since Prettier collapses its two spaces after `7:1` in JSX text. Rows are keyed by their text, which relies on every row being unique (true today).
