# Docs site

## Why the pages are shaped this way

> Source: documented from plan

The end-user docs are the one page that lives in the author's CV site, moved here verbatim and split into an `index.mdx` plus six flat `.md` pages (the rule, command line, configuration, todo conditions, JavaScript API, usage statistics). The split is by sidebar page only: prose, tables and code blocks were not reworded, so the CV page stays a faithful reference for the content.

The pipeline that regenerates the docs on each release tag can only write `website/docs/**/*.md` and the stamp line of `index.mdx`. Three rules follow from that:

- Split pages must be `.md`, never `.mdx`. `publish-docs.sh` rejects any non-`.md` change under the docs, so an `.mdx` split page could never be updated again.
- Split-page front matter holds only `title`, `sidebar_position` and `description`, with no backslash and no `mdx` in it. `description` values are quoted because a YAML plain scalar cannot start with `@` or a backtick. The quote style is single, because Prettier (run by `qoq:fix`) rewrites it; the pipeline does not check it.
- `index.mdx` carries exactly one "verified against" stamp, and no other page does. `update-docs.sh`, `check-docs.sh` and `publish-docs.sh` share the one regex that reads it. A stamp that is missing or doubled fails the docs run at its first step, since `update-docs.sh` and `check-docs.sh` both exit 1 unless exactly one is found. A placeholder stamp such as `v0.0.0` is lower than any tag, so it makes the next tag regenerate the docs from scratch; it must never be committed.

Links between pages use relative `.md` paths, not `#anchors`. `onBrokenLinks: 'throw'` fails the build on a dead page link, but a broken anchor only warns, so anchors would rot unnoticed.

## Who owns what

> Source: documented from plan

`website/docs/**` is regenerated by CI and `website/src/pages/**` is maintainer-owned. The pipeline scripts, `.woodpecker/docs.yml`, `website/.npmrc` and `qoq.website.js` are copied unchanged from the project Template, so a local edit would be overwritten by the next Template sync. Because every release tag pushes a docs sync commit to main, pull before publishing.
